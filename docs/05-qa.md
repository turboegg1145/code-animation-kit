# 05 · 拉片自检：出片前的 15 分钟，省掉一晚上的返工
渲染 720 帧要 3.5 分钟，**但拉片只要几秒**。这一篇讲的就是：在花 3.5 分钟之前，用一张图把「一眼就能看出来的错」全部找出来，再用 ffmpeg 把「眼睛看不出来的错」量出来。
---
## 1. 三档自检，按成本排序

| 档 | 命令 | 时间 | 能发现 |
|---|---|---|---|
| ① 单帧 | `node assets/shot.mjs 0 60 120` | 每帧 ~0.5 s | 构图、字号、配色、中文字体、安全区 |
| ② 拉片（24 格） | `npm run sheet` | 3–5 s | 节奏、停留时长、硬切位置、某段没出现、递归爆栈 |
| ③ 量化 | ffmpeg 四条命令（第 6 节） | 1–3 min | 帧间运动、静止超时、首尾是否相接、亮度跳变 |
**顺序不能反。** ②能发现的问题，③要花一分钟才看得出来；①能发现的问题，②可能糊在小格子里看不见。
---
## 2. 出拉片
### 方式一：命令行（推荐）
```bash
npm run sheet
# 等价于：SHEET=shots/sheet.png SHEET_N=24 SHEET_W=460 node assets/render.mjs frames 7
```

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `SHEET` | 空 | 给了路径 = **只出拉片、不渲视频**（`render.mjs` 在这里就退出了） |
| `SHEET_N` | `24` | 格数 |
| `SHEET_W` | `480` | 每格宽（像素）；格子内部按 **2 倍尺寸**渲染再缩下来 |
| `SHEET_FROM` | `0` | 采样窗口起点 |
| `SHEET_TO` | `total-1` | 采样窗口终点 |
```bash
# 只看第 2 段（第 180–389 帧），出 12 格
SHEET=/tmp/look.png SHEET_N=12 SHEET_W=480 SHEET_FROM=180 SHEET_TO=389 node assets/render.mjs frames 7
# 打印：拉片 12 格 -> /tmp/look.png（180..389）
```
### 方式二：浏览器
打开片子，地址栏加 `?grid=24&cw=460`（可选 `?from=&to=`）：
```
file:///…/assets/skeleton.html?grid=24&cw=460
file:///…/film/index.html?grid=12&cw=480&from=570&to=719
```
### 方式三：页面里直接调
```js
// 控制台
RISO.contact(24, 480, 0, RISO.total - 1)
```
### 尺寸与采样（源码里的公式）
```js
const cols = AR >= 1 ? 6 : 8, rows = Math.ceil(n / cols), cellH = Math.round(cellW / AR), lab = 26, gap = 8;
const SW = cols*(cellW+gap)+gap, SH = rows*(cellH+lab+gap)+gap;   // 底色 '#181818'
const tmp = cvs('cell', cellW*2, Math.round(cellW*2/AR));          // 每格 2 倍渲染
const f = n > 1 ? Math.round(f0 + i*(f1-f0)/(n-1)) : f0;           // 均匀采样
```
举例：16:9、`SHEET_N=12`、`SHEET_W=480` → 6 列 × 2 行、**2936×616**（实测就是这个尺寸）；`SHEET_N=24` → 6 列 × 4 行。竖版（`AR<1`）是 8 列。

**每格 2 倍渲染再缩下来**不是浪费：`post()` 的颗粒/暗角是逐像素的，如果按格子实际尺寸渲染再放大，颗粒会变成大色块，**拉片上看到的噪点和成片不是一回事**。

> `docs/skeleton-sheet.png`（1800×382）是早期版本留下的图，尺寸与当前公式不符——要以 `npm run sheet` 现出的为准。

## 3. 怎么读拉片
每格底部有四个字段（`'12px ' + F_MONO`，颜色 `#ddd`，`textBaseline='top'`）：
```
f=33  poster  t=0.28  1.1s
```

| 字段 | 含义 |
|---|---|
| `f=33` | 全局帧号（也是给你 `shot.mjs` 复查用的帧号） |
| `poster` | plate 名（**这一段是哪一段**） |
| `t=0.28` | 段内进度（0→1）；**用来判「这一段的动作是不是均匀铺开」** |
| `1.1s` | 时间（读停留时长用） |
看三遍：

1. **整体**：四段的色彩/构图是不是四件不同的事？有没有哪一段看起来和别的段「撞了」？
2. **逐格**：文字有没有压物体？有没有哪一格的画面几乎全空？有没有两行字叠在一起？
3. **跟拍**：把格子的时间去对音乐（`f/30` 秒），硬切点是不是落在拍上（120 BPM → 切点应在 0.5 s 的整数倍附近）。

## 4. 逐条 QA 清单
### 4.1 构图与文字

| # | 检查项 | 合格线 | 不合格怎么改 |
|---|---|---|---|
| 1 | **文字不压物体** | 文字所在区域没有结构线/纹理穿过 | 给文字加纸色/底色题签（`pixText` 的 `o.bg`、或先铺一块 `paper` 色矩形），或把物体挪开 |
| 2 | **文字不落在最亮处** | 文字对比度 ≥ 4.5:1 的直觉判断 | 亮底用深字，暗底用亮字；实在躲不开就压一层半透明底 |
| 3 | **不越安全区** | 文字与主体在每轴中央 **92%** 之内（骨架的边缘留白是 `SAFE = 0.07`） | 用 `LW*SAFE` / `LH*SAFE` 定位，不要写死像素 |
| 4 | **没有两行字叠印** | 任何两行字的包围盒不相交 | 用 `textW(g,str,size,weight,font)` 量宽度再排版；卡片式版面改成上/中/下三段 |
| 5 | **字号够大** | 正文 ≥ `LH*0.030`（1080 短边 → 约 32 逻辑像素） | 缩小内容量，别缩字号 |
| 6 | **中文字形正常** | 没有方框/空白 | `fc-list :lang=zh`；字体名用 `F_CJK` |
### 4.2 节奏与运动

| # | 检查项 | 合格线 | 不合格怎么改 |
|---|---|---|---|
| 7 | **停留够读** | 一行字停留 ≥「0.15 s × 字符数 + 0.5 s」 | 拉长 plate 的 `len`（按 `BEAT` 加），或减字 |
| 8 | **每帧都清楚该看哪** | 每格都有一个明确的视觉重心 | 减少同时运动的元素；强调色只留一处 |
| 9 | **没有超过 2 秒的静止** | 任意 2 秒窗口内至少有一个元素在动 | 加最小生命：呼吸缩放（`camPush` 0.5–1.5%）、颗粒、光标闪烁、背景漂移 |
| 10 | **该缓动的地方不线性** | 入出场用 `ease.out*`、段内移动用 `ease.io`、有性格用 `ease.back`/`spring` | 把 `p = span(...)` 换成 `p = ease.out4(span(...))`；成组元素加 `stagger` |
| 11 | **镜头不过快** | 相机一秒内位移 ≤ 画面 20%；大行程留 18 帧（0.6 s）加减速 | 拉长 `camPush` 的覆盖区间，或减小 `from`→`to` 的倍率 |
| 12 | **前 2 秒勾人** | 第 0 帧已经有东西可看 | **起手放在第 0 帧之前**：`span(S.i, -6, BEAT*0.9)`（骨架 `poster` 的朱砂线就是这么做的） |
| 13 | **越接近高潮镜头越短** | 段长递减；高潮前有一个停顿 | 重排 plate 的 `len`；停顿至少 0.5 拍 |
### 4.3 技术

| # | 检查项 | 合格线 | 不合格怎么改 |
|---|---|---|---|
| 14 | **没有突然的亮度跳变** | 相邻帧的 YAVG 变化 < 8（除非是故意的闪/硬切） | 见第 6 节；转场压黑的帧数别太多、硬切前先铺一帧低亮度 |
| 15 | **拉片里没有黑格/重复格** | 每格内容都不一样，没有异常黑格 | 黑格 = 嵌套渲染爆栈或某段自己渲了联系表 → 加 `IN_SHEET` 闸门 |
| 16 | **末帧没有被转场吃掉** | 最后一段的 `cutOut:false` | `plate('phos', {len:…, cutOut:false}, …)`，否则末 3 帧被压黑 |
| 17 | **渲染无失败帧** | `render.mjs` 结尾没有 `N 帧失败`、退出码 0 | 看 `第 N 帧失败：` 与 `页面报错：` |
| 18 | **编码标记正确** | `ffprobe` 显示 `color_space=bt709`、`nb_read_frames` = 期望帧数 | 用 `build.sh`，别自己拼 ffmpeg |
> 这套清单是有代价换来的：成品片按它改过 5 处——ink 的水从随机短线改成分层水平线场（原来像脏点）、标题从压在水纹上改成加纸色题签、pixel 的海从彩色噪点改成 5 档抖动色阶（原来像花屏）、type 第 6 张卡重排成上中下三段（原来两行叠印）、结尾从「淡成白纸」改成「淡回第 0 帧」（原来看起来像播完了）。

## 5. 常见病 → 症状 → 改法

| 常见病 | 症状 | 改法 |
|---|---|---|
| **脏点水** | 水面用「随机位置短线/点」画，看起来像画面脏了 | 改成**分层水平线场**：几条水平基线 + 每层小幅 `ridgePts`，明度按层递减；脏点是各向同性的，水是有方向的 |
| **字压物体** | 文字和纹理撞在一起，两边都看不清楚 | 加题签（纸色底）/挪物体/降低背景对比；别用描边硬扛（描边会变成第三条线） |
| **开场空白** | 第 0 帧几乎全空，2 秒后才开始有东西 | 起手放在第 0 帧之前（`span(S.i, -6, …)`），让第 0 帧就已经在动作中间 |
| **两行字叠印** | 两行字挤在一起/互相穿过 | 用 `textW` 量宽度；版面改成上/中/下三段；长句断行而不是缩字号 |
| **局部帧减全局帧** | 整段动画一直不出现（或所有元素都不动） | `stagger` 的 `t` 传段内帧 `S.i`；跨段要用 `S.i - 段起点`。典型错误：`stagger(S.i - (T0+SHEET_IN), …)` 在段内得到 −542 → 进度永远是 0 |
| **末帧被转场吃掉** | 视频最后一帧全黑（「淡回开头」变成「淡成黑」） | 最后一段 `plate(..., {cutOut:false}, ...)`；转场默认压黑 3 帧 |
| **单层模糊发扁** | 发光字/发光物体像贴了一层灰膜 | 用「密实内芯 + 很淡的大光晕」两层（`glowText` 就是 8 个方向偏移 + `alpha*0.16` + 中心 `0.35`）；不要只做一层模糊 |
| **线性运动** | 所有东西同时匀速移动，像屏保 | 换缓动 + 加错位：`ease.out4(span(...))`、`stagger(t,start,dur,i,n,spread)` |
| **静止帧超过 2 秒** | 盯着看会以为卡住了/视频坏了 | 加最小生命：0.5–1.5% 呼吸缩放、背景漂移、颗粒、光标闪 |
| **嵌套递归爆栈** | 拉片里有黑格；控制台 `Maximum call stack size exceeded` | 加布尔闸门 `let SHEET=null, IN_SHEET=false; if(IN_SHEET) return null; IN_SHEET=true; … IN_SHEET=false;`。**`if(!SHEET) SHEET=buildSheet()` 挡不住**——`SHEET` 要等函数返回才赋值 |
| **`drawImage` 类型错** | `Failed to execute 'drawImage' …: The provided value is not of type '(CSSImageValue or HTMLCanvasElement …)'`（单帧不报，拉片才炸） | `cvs(name,w,h)` **返回画布**、`wipe(g)` **返回上下文**。别写成 `wipe(cvs('a',w,h))` |
| **中文空白** | 中文一个字都不显示，也不报错 | `fc-list :lang=zh`；装 `fonts-noto-cjk`，字体用 `F_CJK` |
| **同一帧颜色不一样** | 换标签页/重跑后同一帧像素不同 | Chrome 必须带 `--disable-accelerated-2d-canvas`（仓库脚本已带） |
| **像素画糊了** | 低分辨率素材放大后发虚 | 整数倍放大 + `g.imageSmoothingEnabled = false`（`pixText` 内部就是这么做的） |
| **饱和色整体偏色** | 纯色看起来偏绿/偏灰 | 编码打 BT.709 标（用 `build.sh`）；别自己拼 ffmpeg |
| **段落撞车** | 相邻两段看起来是同一件事 | 换造型语言（见 `02-style.md` 的表），或至少换色板/字体/运动方式 |
| **音画错位** | 音乐换段了画面还没切 | `SEC_*` 的拍号 × 0.5 s 必须等于 plate 边界的秒数；对照 `RISO.curves()` |

## 6. 量化：用 ffmpeg 量「帧间运动」和「首尾是否相接」
眼睛会被自己的作品骗，数字不会。以下四条都在这部 24 秒成片（1920×1080、720 帧、24.000000 s、bt709）上跑通过。
### 6.1 帧间运动（找静止超时、找「哪段其实没动」）
```bash
ffmpeg -v error -i out/film.mp4 \
  -vf "tblend=all_mode=difference,format=gray,signalstats,metadata=print:key=lavfi.signalstats.YAVG:file=-" \
  -an -f null - \
| awk -F'lavfi.signalstats.YAVG=' 'NF>1 { v=$2+0; s=int(n/30); sum[s]+=v; cnt[s]++; n++ }
    END { for(i=0;i<=s;i++) printf "%2ds  %.2f\n", i, sum[i]/(cnt[i]||1) }'
```
**读法**：数值是「相邻帧平均亮度差」，0 = 完全静止。

| 数值 | 含义 |
|---|---|
| < 0.05 | 几乎完全静止（**危险**：连颗粒都没有） |
| 0.1–0.5 | 有呼吸/漂移（正常的最低限度） |
| 1–3 | 正常的运镜或小元素运动 |
| 3–9 | 有明确动作（入场、扫入、爆点） |
| > 15 | 硬切/闪（一秒里只有 1–2 帧这样是正常的） |
实测（同一部片子，每秒均值）：
```
0s 0.36   1s 0.13   2s 1.16   3s 1.11   4s 0.31   5s 7.56
6s 0.17   7s 0.20   8s 0.28   9s 0.26  10s 0.20  11s 0.14
12s 8.68  13s 4.67  14s 8.49  15s 1.27  16s 1.83  17s 2.97
18s 5.68  19s 0.12  20s 0.25  21s 0.06  22s 0.15
```
判读：5 s / 12 s / 14 s / 18 s 是动作峰值（涌流、硬切、揭示、riser 收尾）；**21 s 的 0.06 是最低点**——那一秒几乎完全静止（outro 的长音 + 缓慢推镜），如果它超过 2 秒就违反了清单第 9 条。
### 6.2 首尾是否相接（做「淡回开头」时要查）
```bash
# 把第 0 帧和第 719 帧叠起来做差，取唯一输出帧的 YAVG
ffmpeg -v error -i out/film.mp4 \
  -vf "select='eq(n\,0)+eq(n\,719)',tblend=all_mode=difference,signalstats,metadata=print:key=lavfi.signalstats.YAVG:file=-" \
  -an -f null -
# lavfi.signalstats.YAVG=15.360854
```
YAVG = 15.36 表示**同构图但不同像素**（不是逐像素相同）。想更严格就比原始 PNG：
```bash
ffmpeg -v error -i frames/f00000.png -i frames/f00719.png -lavfi "[0:v][1:v]psnr" -f null -
# average:22.70
# 对照：相邻帧 f00000 vs f00001
# average:34.10
```
**判据**：首尾 PSNR 应该**明显低于相邻帧**（差 10 dB 以上），但**不能是 0（全黑）**。本片 22.70 vs 34.10，符合「回到同一个构图，但末帧是自己算出来的」这个意图。
### 6.3 硬切位置（对拍）
```bash
ffmpeg -v error -i out/film.mp4 \
  -vf "select='gt(scene,0.25)',metadata=print:key=lavfi.scene_score:file=-" -an -f null -
```
实测命中：
```
pts_time:5.9   scene_score:0.566
pts_time:6.0   scene_score:0.290
pts_time:12.9  scene_score:0.287
pts_time:13.0  scene_score:1.000     <- 最硬的切（瑞士海报段）
pts_time:14.0  scene_score:0.264
pts_time:15.0  scene_score:0.257
```
**每个 `pts_time` 都应该是 0.5 s（一拍）的整数倍附近**，并且必须落在 plate 边界（6.0 / 13.0 / 19.0）上。偏了就是音画错位。
### 6.4 亮度跳变（找「闪了一下」）
```bash
ffmpeg -v error -i out/film.mp4 \
  -vf "signalstats,metadata=print:key=lavfi.signalstats.YAVG:file=-" -an -f null - \
| awk -F'lavfi.signalstats.YAVG=' 'NF>1 { v=$2+0; if(n>0 && (v-p>8 || p-v>8)) printf "帧 %d  Δ%+.1f\n", n, v-p; p=v; n++ }'
```
实测（只列变化超过 8 的帧）：
```
帧 177–179  Δ-66 左右     <- 转场压黑 3 帧
帧 180      Δ-99.7        <- 硬切入 pixel（暗）
帧 387–389  Δ-33.5 左右   <- 转场压黑 3 帧
帧 390      Δ+230         <- 硬切入 type（白）
帧 400      Δ+12.9 / 450 Δ+24.1 / 510 Δ+21.9   <- type 段换卡
帧 62       Δ+8.5
```
**判读**：转场压黑、硬切、换卡带来的跳变都是**故意的**；除了这些之外还出现 > 8 的跳变，就是 bug（通常是某个元素的 `alpha` 用了 `span` 但没接缓动，或者突然从 0 变 1）。

## 7. 一轮完整自检的流程
```bash
# 1) 三个关键单帧看一眼（快）
node assets/shot.mjs 0 90 419

# 2) 出拉片（4 秒）
SHEET=shots/sheet.png SHEET_N=24 SHEET_W=460 node assets/render.mjs frames 7

# 3) 按第 4 节清单逐条过（这一步不能省，也不能跳着看）

# 4) 全片渲染（3.5 分钟）
node assets/render.mjs frames 7

# 5) 编码 + 自动校验（音画时长、bt709、帧数）
bash assets/build.sh

# 6) 量化自检
ffmpeg … tblend …（6.1 帧间运动）
ffmpeg … select eq(n,0)+eq(n,719) …（6.2 首尾）
ffmpeg … gt(scene,0.25) …（6.3 硬切）
ffmpeg … signalstats YAVG …（6.4 亮度跳变）
```
第 3 步和第 6 步是**两套独立的检查**：清单查「意图有没有实现」，量化查「实现有没有意外」。两套都过，才算能给人看。

## 8. 把别人的意见变成改法
* **先给关键帧，别给成片**。挑 3–5 帧（第 0 帧 + 每段的代表帧）给人看，改构图只要几分钟；渲完成片再改就是 3.5 分钟起。
* **把反馈落到参数上**。人说「有点空」，你要决定的是：plate 的 `len` 加 2 拍、还是加一个次要动作、还是推镜从 6% 加到 10%。落不到参数的反馈等于没收到。
* **改完只重渲那一段**：
```bash
# 改的是第 390–569 帧（type 段）
rm -f frames/f003{90..99}.png frames/f004{00..99}.png frames/f005{00..69}.png
START=390 END=570 RESUME=1 node assets/render.mjs frames 7
bash assets/build.sh
```
* **改一处，重跑一次第 6.1 节**。改动的常见副作用是「把某一段改静止了」——那一条命令 30 秒就能发现。

## 9. 速查
```bash
# 出拉片
SHEET=shots/sheet.png SHEET_N=24 SHEET_W=460 node assets/render.mjs frames 7
# 浏览器里
#   ?grid=24&cw=460        全部
#   ?grid=12&cw=480&from=570&to=719   只看第 4 段
```

| 亮度 | 除转场/硬切外没有超过 8 的 YAVG 跳变 |
